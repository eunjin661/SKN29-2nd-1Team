## 1. 분석 화면을 실제 자료와 연결

### 무엇을 어떻게 바꾸는가

- `backend/api/routes/eda.py`와 `frontend/src/hooks/useEDA.js`의 고정 통계를 제거하고 저장된 이벤트 자료에서 카테고리 수·개수·중앙/평균 지속시간·연도별 비중·요일·순위 분포·24h 관측 여부를 계산한다.
- 화면 전체와 관련 CSV에 자료 출처, 관측 기간, 계산에 사용한 표본 수와 제외 수를 전달한다. API는 집계 결과를 제공하고 화면은 검증·표시에 집중한다.
- 전체 과거 관측의 34,964 이벤트와 모델 평가 표본을 구분한다. TDI 그래프는 현재 v2의 분할·라벨 생성 규칙과 Train 통계를 사용하고, 해당 계산 대상의 N을 표시한다. 모든 그래프의 N을 억지로 34,964에 맞추지 않는다.
- TDI histogram의 막대 합계는 그 그래프의 유효 표본 N과 같아야 한다. 값이 없는 행, 시간 오류, 분할 제외 등은 사유·개수로 기록한다.
- EDA의 고정 해설도 집계 결과에 맞춰 갱신한다. 예를 들어 실제 최다 요일과 무관하게 금요일이라고 쓰는 경로를 없앤다.
- Feature Engineering·문제 정의 화면은 현재 사용하는 수치 9개와 카테고리 1개, v2 정답과 평가 범위에 맞춘다. 확인되지 않은 24h 모델·기여도·과거 모델 성능을 현재 결과로 표시하지 않는다.
- 인사이트·전략 화면은 실제로 계산 가능한 관측 비교를 제공한다. 인과 효과·예상 성장·최적 집행 시각으로 확대 해석하는 고정 문구를 정리한다.
- 원본 할당·실험 근거를 확인할 수 없는 클러스터 점유율·p값·중요도는 사용 불가로 표시한다. 검증하지 않은 값을 다른 고정값으로 바꾸지 않는다. 수학적 sin/cos 설명 그림은 실제 데이터 분석과 구분해 유지한다.
- 자료가 없거나 응답이 잘못되면 로딩·오류·재시도 상태로 처리한다.

### 사용자에게 보이는 변화

그래프 수치와 설명이 실제 집계에 따라 바뀌고, 각 자료의 출처·기간·표본 수를 확인할 수 있다. 근거 없는 차트·카드는 비어 있는 이유를 표시하거나 제거한다. 기존 색상·탐색 구조는 활용하고 수치와 설명을 중심으로 수정한다.

### 검증

소규모 표본의 수작업 기대값과 집계 비교, 카테고리·요일·구간 합계 일치, 평균과 중앙값 구분, 누락·잘못된 값의 제외 처리, 입력 자료 변경에 따른 출력 변경, 서버 실패 시 임의 수치 없음, 현재 예측·평가 화면의 회귀 동작을 확인한다.

## 2. 캠페인을 가정이 드러나는 계산기로 정리

### 무엇을 어떻게 바꾸는가

- 캠페인 API와 화면의 임의 ROI 지수, 점수 기반 전환율, 검증되지 않은 위험 등급·집행 강도·AI 추천 문구를 정리한다.
- 사용자는 총예산, CPM, CTR, CVR, 카테고리별 예산 배분을 입력한다. CTR은 노출 대비 클릭률, CVR은 클릭 대비 전환율로 정의하고 단위를 표시한다.
- 화면은 관측 카테고리의 이벤트 수·지속시간 등 확인 가능한 참고 정보를 함께 보여준다. 광고 효과를 입증한 자료로 표현하지 않는다.
- 계산식은 다음으로 고정하고 화면에서 확인할 수 있게 한다.
  - 노출 수 = 예산 ÷ CPM × 1,000
  - 클릭 수 = 노출 수 × CTR
  - 전환 수 = 클릭 수 × CVR
  - CPA = 예산 ÷ 전환 수
- CTR·CVR은 모델이 만든 값으로 채우지 않는다. 샘플 조건은 별도 버튼으로 입력하고 가정임을 표시한다.
- 전환 수 0이면 CPA는 계산 불가로 표시한다. 결과를 만들기 위해 분모를 1로 바꾸지 않는다. 음수·비정상 수·범위 초과를 거부하고 카테고리 배분 합계와 총예산을 맞춘다.
- CSV에는 입력 가정·단위·계산 결과를 함께 내보낸다. 외부 문자열의 인용·수식 해석 처리는 기존 공통 도우미를 사용한다.

### 사용자에게 보이는 변화

ROI 지수·AI 위험 등급·자동 집행 결론이 있던 영역은 입력 조건과 계산 결과를 확인하는 영역으로 바뀐다. “CTR 1%, CVR 2%를 가정했을 때의 결과”처럼 계산의 전제를 드러낸다.

### 검증

알려진 예산/CPM/CTR/CVR 조합의 기대값, 입력 변경 갱신, 비율·예산 배분 합계, 전환 0·CPM 0·음수·비정상 입력, 화면과 CSV 값 일치를 확인한다.

## 3. 성능 변동·오탐 근거를 추가

- 현재 `t0-v2-cpu-20261022-audit`와 그 모델·지표를 기준 기록으로 보존한다.
- 선택한 Embedding MLP를 시드 **13·29·42·73·101**로 평가한다. 분할·피처·하이퍼파라미터·모델 선택 규칙·Validation 임계값 선정 절차를 실행 전에 고정한다. 동일 조건의 기존 시드 42 결과는 출처를 확인해 활용한다.
- 시드별 Validation/Test 지표, 평균·표준편차, 실행 시간·실패를 새 실험 ID에 기록한다. 가장 잘 나온 Test 시드를 현재 모델로 자동 교체하지 않는다.
- 저장된 Test 예측을 이용해 **video_id 단위로 2,000회 재표집**한다. 같은 재표집 인덱스를 기준 모델과 선택 모델에 적용해 AUC·F1 등과 차이의 95% 재표집 구간을 기록한다. 유효 반복 수·난수 시드도 저장한다.
- Validation에서 임계값별 정밀도·재현율을 계산하고 현재 임계값 0.44의 위치를 표시한다. Test의 오탐 수와 한계도 함께 설명한다.
- 모델 화면·근거 문서에 변동과 오차 범위를 추가한다. 기존 Test를 이용한 진단이라는 사실을 표시하고 새로운 외부 기간 검증으로 주장하지 않는다.

완료 기준은 점수 상승이 아니라, 점수의 변동·오탐·비교 조건을 근거와 함께 설명할 수 있는 상태다. 결과가 기대보다 낮아도 그대로 기록한다. 현재 CPU/WSL에서 순차 실행한다.
