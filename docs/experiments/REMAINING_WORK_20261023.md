### R01. EDA와 기존 분석의 수치 출처 정리 — 최우선

- `frontend/src/hooks/useEDA.js:73`의 양성 비율 34.5, `:76`의 연도별 비중, `:88`의 TDI histogram, `:97`의 요일별 빈도, `:105`의 24h 관측 비율이 상수다. API 응답이 성공해도 해당 필드를 실제 자료에서 계산하지 않는다.
- 고정 TDI bin `[10910, 7170, 4830, 6640, 5420, 3470, 2590, 1760, 1230, 944]` 합은 **44,964**다. 선언된 이벤트 **34,964**보다 **10,000** 많다. 구간 정의와 표본 일치 검사가 필요하다. `frontend/src/pages/EDACharts.jsx:103`이 이 배열을 직접 사용한다.
- `backend/api/routes/feature.py:14`는 `fallback_safe` 응답을 반환한다. 전략·인사이트·문제 진단에도 레거시 AI 점수·고정 전략 값이 남아 있어, 폐기한 weighted voting과 검증 T0 v2가 같은 근거로 읽힐 수 있다.
- 조치: 각 수치를 실제 관측 자료에서 집계하거나, 출처·버전이 있는 과거 실험 결과로 표시한다. 근거를 확인할 수 없는 항목은 숨기거나 사용 불가로 표시한다. 과거 TDI와 v2의 정의를 명확히 한다.
- 완료 기준: histogram 합계와 해당 표본 수 일치, 범주별 합계·단위·기간 검증, 입력 자료 변경에 따른 실제 값 갱신, 자료 없음·계약 불일치에서 임의 수치 없음. 기존 동작 테스트에 별도 데이터 의미 검사를 추가한다.

### R02. 캠페인 수치를 검증된 범위로 축소 — 최우선

- `frontend/src/pages/CampaignPlannerPage.jsx:120`은 점수에 위험도별 **1.45 / 1.18 / 0.82**를 곱해 ROI 지수를 만든다.
- `:126`의 예상 행동 수와 `:127`의 행동당 비용은 **0.025 + 점수 / 2500**이라는 전환 가정을 사용한다. 현재 확인한 코드에는 실제 광고 성과로 이 계수를 검증한 근거가 없다.
- 서버 `backend/api/routes/campaign.py`도 관측 지속시간·TDI·이벤트 수 등에 가중치를 주어 추천 점수를 만든다. 이 값은 검증 T0 분류 모델의 출력이나 실제 ROI가 아니다.
- 조치: 근거 없는 ROI·전환 예측은 제거한다. 유지할 예산 기능은 사용자가 입력한 CPM·전환율 가정에 따른 계산기로 정의하고, 가정과 산식을 화면·CSV에 함께 남긴다. 과거 지속시간만으로 광고 효과·장기 수익을 단정하지 않는다.
- 완료 기준: 관측값·모델 출력·사용자 가정·계산 결과의 출처가 구분되고, 검증하지 않은 사업 효과가 예측 성능으로 표시되지 않는다.

### R03. 모델 평가의 불확실성과 오탐 설명 — 다음 순위
