# TrendIt 개선 계획과 완료 기준

기준: 2026-10-22. 작업 브랜치: `improve/trendit-reproducibility`.

| 순서 | 작업 | 완료 기준 |
|---|---|---|
| 1 | 기존 실험 보존과 누수 경로 격리 | 기존 바이너리를 덮어쓰지 않고, 누수 메타데이터에 폐기 상태와 이유 표시 |
| 2 | 공통 데이터·평가 계약 | T0 입력 허용 목록, 시간순·영상 분리, 미확정 라벨 제외, 학습 구간 통계로 TDI 생성 |
| 3 | 기본 모델·개인 딥러닝 재현 | 같은 분할로 Dummy·Logistic·XGBoost·LightGBM·앙상블·MLP·TabNet 실행 |
| 4 | 재발 방지와 재현 안내 | 누수·그룹 중복·학습 전처리·산출물 검증 테스트, 고정 의존성, 실행 명령 |
| 5 | 실제 결과 공개와 추론 확인 | 데이터·소스 해시와 모델별 결과 저장, 저장 모델 재로딩 일치, 명시적 v2 API 검증 |

## 평가 원칙

- Train / Validation / Test 경계는 T0 순서의 약 70% / 85% 시각으로 정한다. 같은 시각은 양쪽에 나누지 않는다.
- 이전 분할에 나온 `video_id`는 이후 분할에서 제외한다. 새로운 영상에 대한 시간적 일반화를 평가한다.
- 마지막 관측 후 6시간이 지난 시점까지 결과를 확인할 수 있는 이벤트만 사용한다. 경계를 넘는 라벨과 우측 검열을 제외한다.
- 카테고리별 지속 시간 95분위수는 학습 구간에서만 추정한다. 기존 전체 기간 TDI와 직접 성능 비교하지 않는다.
- 초기 조회수·댓글·순위·발행시각으로 피처를 다시 생성한다. 기존 파생 컬럼, 지속 시간, 다른 라벨, 24h 증가량, 포화도는 입력하지 않는다.
- 모델 선택과 임계값 결정은 Validation에서 끝낸다. Test 결과로 모델이나 설정을 고르지 않는다.
- 성능이 낮아져도 확인한 값을 기록한다. 기존 발표 수치는 역사 자료로 구분한다.

## 범위

이번 작업은 T0 분류의 재현성과 검증을 완성한다. 기존 화면의 휴리스틱 혼합 예측, 지속 시간 회귀, 24h 업데이트, 실제 운영 성능은 별도 범위다. 새 API는 정확한 초기 관측값을 받으며, 현재 영상 통계를 T0 값으로 가장하지 않는다.

진행 결과와 남은 제한은 `docs/experiments/t0_v2_report.json`과 `docs/experiments/T0_V2_RESULTS.md`에 기록한다.

## 2026-10-22 완료 확인

위 1~5단계를 완료했다. 실험 `t0-v2-cpu-20261022`는 CPU에서 8종 비교를 67.16초에 마쳤다. 새 가상환경의 잠금 파일 설치와 의존성 검사가 통과했다. 회귀 테스트 19개가 통과했고, 저장 모델 8종의 재로딩 예측이 각 16개 사례에서 원래 예측과 오차 1e-6 이내로 일치했다. 새 API 상태·분류 요청은 HTTP 200이며 폐기 앙상블의 자동 로딩 차단을 확인했다.

VS Code는 저장소의 `.venv`를 기본 인터프리터로 사용한다. F5의 `TrendIt T0 v2 API` 구성으로 생성된 실험을 지정해 실행할 수 있다. 테스트 도구의 HTTP 클라이언트 전환 예정 경고 1개는 남아 있다.

검증 기록: `docs/experiments/t0_v2_verification.json`.

후속 개선 후보: 독립된 시간 구간/반복 시드 검증, 반복 영상 이벤트 평가, 기존 화면의 v2 API 연동, 실제 사용자 효과 측정. 이번 결과를 과거 실험 대비 향상이나 운영 성능으로 제시하지 않는다.
